# Idea 探索与更新

Idea 中心回答三个问题：哪些研究问题值得投入、具体可以怎样做、先做什么实验最有信息量。使用 `research-lit → idea-creator → novelty-check → research-review`，结合本库与外部一手文献。研究建议应有明确立场，也应给出可以改变这个判断的证据。

## 1. 建立问题地图

先阅读当前方向综述、本库近期报告和历史候选，归纳已经解决的问题、正在变化的方法和有价值的新能力。历史否定记录说明当时的证据，不自动决定新候选的命运。

执行 `npm run review:preflight`、`npm run idea:preflight`，并使用 `npm run review:prompt -- <direction-id>` 生成方向检索要求。新一轮生成提示使用 `npm run idea:prompt -- <direction-id> explore`。

- 本库用于发现线索、方法接口和研究兴趣，不作为文献全集。
- 检索覆盖最近六个月的并发工作、近三至五年的直接近邻和必要奠基工作；保留正式版与 arXiv 双入口。
- 外部补查至少包含任务近邻、功能等价机制和相邻领域。协同方向还要阅读通信与控制文献。
- 阅读最近邻的方法、实验和适用条件；记下实际阅读深度。目录命中、摘要阅读和全文核对分别计数。
- 对重要方法比较，引用各论文自己的原文。数据、代码、配置和权重分别核查，明确复用与自建部分。

输出每方向两段：**进展如何改变了问题**，以及**下一步最值得尝试的能力或机制**。不要把研究议程写成限制清单。

## 2. 发散生成

按 `idea-creator` 使用两种生成模型，对同一证据包独立思考，再合并候选。完整保存各自的输出与来源，只合并实质重复项。覆盖各研究方向，同时寻找跨方向的共同问题。

候选先写方法：用两到四步说清构建、训练或运行什么。再解释为什么可能有效、将揭示什么，以及最便宜的验证方式。考虑直接方法、跨领域连接和高风险高收益路线，避免候选全部成为评测修补或保守筛选器。

研究密集说明问题重要；需要实现适配器、模型、数据处理或闭环是正常研究工作。成熟方法迁移若能揭示新的机制、交互或结论，也可以构成贡献。不要为了避开所有质疑不断叠加模块或缩小问题。

## 3. 比较与查新

对每个候选解释最近邻已经做到什么、这里要改变什么。用机制同义词、相邻任务和近半年文献交叉查询。

- 有清楚差分：继续。
- 差分尚有争议：指出争议落在哪里，用实验或更深入阅读解决。
- 已有具体论文包含同一结果：写明论文与重合范围，合并、改变问题或暂存。

相邻工作和并发竞争本身不是否定理由。未经运行的假设不能被写成结果，但仍可作为值得试验的研究建议。

## 4. 候选写作结构

每个候选包括：

- **方法**：两到四个具体步骤，保持一个清楚的核心机制。
- **假设与价值**：期待改变什么能力或认识，为什么现在适合做。
- **最近邻比较**：至少两项直接比较，附可定位的一手来源。
- **实现路径**：可复用的数据、代码与模型，需要自行实现的模块，以及关键依赖。
- **首项实验**：问题、数据与划分、强基线、测量指标、统计单位、预算。
- **结果解释**：什么支持假设；什么反对假设；什么只说明当前试验仍不充分。
- **风险与后续**：最具体的风险，以及实验之后如何推进。
- **阅读依据**：同时保留本库与外部文献，说明来源对本候选的实际作用。

预算是计划，不是实测。未运行的实验统一标为“尚未运行”；不要用示例数字、合成 fixture 或结构检查代替真实任务结果。

## 5. 独立比较与投入建议

由未参与检索和方案撰写的评审者阅读候选和一手来源。评审同时回答：这项工作最强的价值是什么、主要风险是什么、哪项实验最能决定下一步。

逐项给出以下建议并解释理由：

| 状态 | 含义 |
| --- | --- |
| 优先试验 `pilot` | 方法差分清楚，首项实验的成本与信息量值得投入 |
| 继续展开 `develop` | 值得研究，先补最近邻比较、变量定义或实现设计 |
| 暂存 `park` | 当前优先级较低，写清具体原因与重新考虑条件 |

这些状态是研究投入判断。它们不表示实验已经通过，也不使用“所有评审满分”代替探索。不要预设必须淘汰多少候选；不要只选最安全的方案。

## 6. 保存与展示

新轮次保存到 `content/idea-explorations/<YYYY-MM-DD>.json`，由 `content/idea-center.json` 的 `currentExplorationId` 指向。各方向先展示本轮问题地图、候选方法和首项实验；相关工作与详细实验可展开阅读。搜索索引收录研究内容，不收录重复审计台账。

沿用已有快照绑定方式，独立内容复核后保存真实评审者、逐候选建议和最终文件指纹。原始生成、查询、查新与评审记录保存到对应 `docs/center-updates/` 目录。只在实际重检后刷新日期。

历史正式盲评继续按其原始工作流核验。原候选 ID、分数、评审原文、通过或否定状态不回写；新探索与历史“全项通过”分别展示。历史深链接、折叠展开、搜索与打印均应可用。

## 7. 验收

运行预检、内容验证、测试和正式 Pages 构建。检查十个方向的覆盖、来源链接、当前候选与历史记录的区分，并在桌面及 390 px 页面核对阅读、方向切换、搜索、深链接和打印。部署后核对最终提交和线上资源。本轮只更新研究中心时，不改写已经发送的简报来触发通知。
