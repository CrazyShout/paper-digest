# Idea 探索模板

这个模板用于把一个宽泛研究方向压缩成少量可证伪、可止损的研究 Idea。它和简报筛选是两套任务：简报回答“近期哪些论文值得读”，Idea 探索回答“这个问题是否值得投入、是否还有突破余量、我们具体能验证什么”。

## 使用原则

- 本站已收录论文只作为检索种子和组内兴趣约束，不能代替完整相关工作检索。
- 关键判断优先引用会议官方 proceedings、论文 PDF、项目页、作者代码仓库和 arXiv 原文。
- 先审计方向，再生成 Idea。任一硬门槛未通过时，记录淘汰原因，不为了数量继续包装。
- 每个结论区分“论文明确报告”“跨论文归纳”和“研究假设”，不要把推断写成事实。
- 可做成度衡量形成可信研究结果的可行性，不等于论文录用概率。

## 1. 定义方向

```text
方向名称：
边界：包含什么、不包含什么
目标用户或系统：
核心失败：
失败代价：
本轮检索日期：
检索时间范围：默认近 3–5 年，并追溯奠基工作
```

先把“提升感知”“增强鲁棒性”这类宽泛目标改写成可观察问题。例如：

```text
当远端信息因时延和位姿漂移变得有害时，融合器能否在写入前识别并拒绝？
```

## 2. 意义审计

至少回答：

- 谁会受到这个失败影响，影响是安全、性能、成本还是科学解释？
- 失败在真实系统、公开 benchmark 或多篇论文中是否重复出现？
- 现有主指标是否能观察到这个失败？如果不能，需要什么新指标？
- 不解决它会阻止哪类部署或后续研究？
- 这个问题是否只是把已饱和榜单再提高一个小数点？

输出一段可核验的继续 / 淘汰判断。若缺少真实代价、一手证据或可观察后果，直接停止，不用主观分数替代证据。

## 3. 前沿检索

### 查询族

每个方向至少覆盖以下四类查询：

```text
任务名 + failure / limitation / robustness / deployment
任务名 + benchmark / real-world / sim-to-real / closed-loop
候选机制 + 同义词 + 相邻领域方法
最接近论文 + citations / follow-up / negative result
```

### 证据表

每条核心证据记录：

```text
论文：
年份 / venue：
官方链接：
解决的具体问题：
关键假设：
数据、指标和最强结果：
代码 / 数据可用性：
仍未覆盖的失效条件：
与候选 Idea 的碰撞风险：
```

不要仅按标题判断。至少阅读摘要、方法图、主要实验、限制和补充材料；对最接近的 3–5 篇工作需要读到足以复述其机制和评价边界。

## 4. 余量与饱和度审计

把子问题分为三类：

### 高竞争区

- 近两年工作密集，强基线持续刷新。
- 常见机制和数据集组合已经重复出现。
- 贡献容易退化为换 backbone、叠模块或调损失。

### 疑似极限区

- 指标接近数据标注、传感器或评价协议的上限。
- 近年增益主要来自数据、模型规模或昂贵硬件。
- 剩余差距没有可测的失败集合，或最小实验无法区分方法优劣。

### 仍有余量

- 强方法在真实约束、组合扰动、长尾或跨域下重复失败。
- 主指标掩盖了风险、成本、闭环影响或恢复能力。
- 相邻领域存在尚未迁移的成熟机制。
- 新数据、平台或工具让此前不可验证的问题首次可测。

输出“高竞争 / 疑似极限 / 仍有余量”的结论和证据。只有落在可测余量、并且改变问题定义或验证对象的候选才能继续。

## 5. 新颖性碰撞

对每个候选机制执行：

1. 搜索机制名、任务名、同义词和组合关键词。
2. 检查最接近论文的引用与后续工作。
3. 搜索相邻任务中功能等价的方法，而不只匹配术语。
4. 写一段“最近工作已经做到什么 / 本 Idea 多做什么 / 为什么不是简单组合”。
5. 预先写出最可能的审稿人质疑，并说明什么实验能回答。

输出“保留 / 修订 / 淘汰”结论。功能等价工作已经覆盖研究对象，或差异只来自改名、换骨干、拼接模块时直接淘汰。

候选池冻结后，再由未参与检索和方案撰写的筛选者只根据候选 ledger、查询审计、一手证据和固定资产独立决定 shortlist。筛选报告必须覆盖每个候选，记录 `shortlist` / `reject` 与证据化理由，并绑定候选池 SHA-256 快照；历史 shortlist、后续 dossier 和盲评分数不得出现在筛选输入中。检索者、筛选者和盲评者的身份在整个 Idea 中心范围内互斥。

## 6. 解法空间扩展

通过前三道门槛后，至少探索三类路线：

- 保守路线：复用最强公开基线，只改变关键决策或目标函数。
- 跨领域路线：从不确定性、控制、因果、安全、优化或系统领域迁移机制。
- 高风险路线：允许改变评价协议、数据采集或系统接口，但明确新增依赖。

每条路线写清：核心机制、必要假设、训练信号、推理接口、计算和通信代价、最可能失败点。

需要自行实现适配器、模型模块、评测器、数据处理或实验闭环是正常的研究工作，不能单独构成淘汰理由。必须把“已有可复用资产”“需要自行实现的部分”“尚未核验的依赖”分开记录。

## 7. 最小研究闭环

```text
核心假设：一句可被实验推翻的话
数据：至少一个启动集，优先再加一个跨域验证集
强基线：直接竞品、简单基线、oracle / lower bound
扰动或场景：覆盖候选 Idea 真正声称解决的失败
指标：主任务指标 + 风险 / 成本 / 校准 / 闭环指标
消融：每个新机制至少有一个可解释消融
周期：6–12 周内能否得到 go / no-go 结论
```

必须同时写：

- 成功标准：定量到足以决定是否继续。
- 停止条件：什么结果说明核心假设不成立。
- 主要风险：数据代理失真、评价泄漏、强基线复现、资源和部署依赖。

输出“现成可执行 / 可信自建路径 / 需补关键证据 / 不可执行”结论。可行性的核心是实现路径可信且最小实验可证伪，不要求已有开箱即用代码、固定 checkpoint 或完整现成闭环。只有关键数据依法不可得、核心干预不可观测、最小实验不能识别主张，或周期超出上限时，才因可行性不得送入盲评。

## 8. 单个 Idea 发布结构

每个通过门槛的 Idea 使用一致结构：

```text
标题：能指出决策或机制，不用泛化口号
一句切口：为什么这个切口值得立刻看
推荐顺位：
决策：首选 / 低成本首发 / 稳健方法线 / 高风险高收益
首轮周期：
预期产出：方法 / 数据 / 评测协议 / 系统

为什么是现在：
关键问题：
现有工作不足：
新颖性边界：2–4 条，逐条说明最近邻已经做到什么、这里多做什么
可证伪假设：
解决机制：3–5 条
实现路径：列出复用资产、自建模块、依赖和工程里程碑
最小研究闭环：3–6 条
强基线：至少 3 个直接竞品、简单基线或 oracle / lower bound
评价指标：主任务指标、风险 / 成本指标和统计单位
继续投入的证据：2–4 条
停止条件：至少 2 条
主要风险：至少 2 条
潜在影响：说明正结果和负结果分别会改变什么
关键相关工作：4–7 篇一手论文及其具体作用，明确本库与外部证据来源
```

## 9. 评分

前置检索、资产检查和新颖性碰撞只负责硬门判断，不使用主观加权总分。通过硬门的候选统一交给隔离盲评者，按 `config/idea-exploration-workflow.json` 的五个维度各自给出 1–10 分：

```text
新颖性
实现可行性
成功率
影响力
前人实验可对比性
```

每位评估者还必须给出总体分、逐维证据、最强反对意见和必做实验。主流程只读取评估者实际返回的结果，并按工作流中配置的发布分执行；发布分不得写入评估提示，也不得要求评估者猜测。

## 10. 更新与淘汰

- 新顶会论文直接覆盖候选机制时，立即重做新颖性碰撞。
- benchmark、代码或数据变化影响可行性时，更新维度分数和日期。
- 最小实验触发停止条件时，将 Idea 标记为淘汰并保留原因，不静默删除失败证据。
- 每次新增正式简报后，检查是否出现会改变问题地图、饱和判断或强基线的新论文。

## 11. 独立盲评与最终复核

候选在完成前沿检索、新颖性碰撞和最小研究闭环后，必须交给彼此隔离的独立评估者。至少覆盖以下五种审阅视角：

- 新颖性：检查功能等价的最近工作、并发工作和撞题风险。
- 实现可行性：检查公开代码、数据、算力、依赖和工程周期。
- 实证成功率：检查假设证据、指标、统计功效、消融和止损条件。
- 影响力：检查正负结果是否都能改变系统设计、科学认知或评测协议。
- 前人实验可对比性：检查直接竞品、强基线、公平比较和复现边界。

每位评估者都必须独立给出全部五个维度的 1–10 分、证据、最强反对意见和必须修改项。评估者之间不得共享结果，评估提示不得包含或暗示主流程的接受阈值。未通过主流程判定的候选只能修订后交给新的评估者重审，或记录到淘汰台账。

盲评可以顺序执行或先并行启动两个互补视角。任一已提交报告出现不满足发布分的维度或总体分时，本轮不可能再获得全体一致结论，应标记为 `early-rejected`，停止尚未启动的其余视角并保存实际报告；不得通过均分、删除低分报告或补找宽松评估者改变结论。只有此前报告均满足发布分时，才继续补齐全部五种 lens；最终发布的 Idea 仍必须拥有五个独立视角的完整报告。

每位评估者使用独立 lens 提示生成评审任务：

```bash
npm run idea:prompt -- <direction-id> evaluate <lens-id> <candidate-id>
```

`lens-id` 分别覆盖新颖性、实现、实证、影响和基准复现。主审 lens 只决定优先核查的证据，不免除对另外四个维度的独立评分。评审输出还要记录实际重新打开的一手证据，不能只复述候选档案。

每份 dossier 在送审前记录 `frozenAt`。每份评审原始 JSON 单独存入 `content/idea-audits/`，发布数据通过 `reportPath` 引用它。原始报告中的 `candidateId`、`lens`、`reviewerAgentId`、`reviewedAt`、`dossierSnapshotFingerprint`、逐维分数、理由、异议、必做实验和总体分必须与发布台账逐项一致；至少重新打开两项 HTTPS 一手证据。评审时间不得早于 dossier 冻结时间，主数据中的摘要不能代替原始报告。

七个方向全部完成后，另启一个不参与检索、筛选或方向级评估的独立评估者，对全库 Idea 的覆盖、证据、新颖性、可行性、影响力、可比实验和跨方向重复进行最终复核。该评估者必须逐方向重开一次方向 artifact 集，并为每个方向至少重开一项 HTTPS 一手证据；原始 JSON 同样存入 `content/idea-audits/`。最终报告绑定中心快照及逐方向 artifact 快照，后者包含候选池、独立筛选、dossier 和实际盲评报告；任何后续正文、引用、评分或检索审计变化都会使旧结论失效。
