## 本期判断

本期八篇涵盖协同定位、通信压缩、时序记忆、世界—动作建模和评测。值得一起看的是收益与代价：遮挡下的状态可用性不等于定位误差下降，规划总分提升也可能伴随效率下降。各篇的对照设置和失败项放在后文比较。

## 论文对照

Multi-Observer 与 G-MARK 分别评估多源定位和协同语义信息。Multi-Observer 真实路口实验报告了以下结果：完整刷新率下 LiDAR-only RMSE 为 0.84 m，融合 AEKF 只到 0.81 m，radar-only match rate 仅 0.215；人工遮挡时雷达也没有降低定位误差，只在较长遮挡里略微保住轨迹可用率。G-MARK 给出另一种协同处理方式，不急着把多车证据压成单一状态，而保留来源、ego/partner 可见性、不确定性和冲突，使遮挡推理提升 42.2%，同时把结构化通信量降到 V2V-GoT 的约 1/25.6。两篇可对照信息来源的保留方式，以及新增信息是否改善各自任务。

两篇端到端规划论文分别处理交通规则对象与历史记忆。Traffic Element Awareness 把交通灯、标志的三维位置及其 ego-lane topology 显式接入六种规划器，Bench2Drive 中 VAD Driving Score 从 42.3 升到 56.4、DriveTransformer 从 63.46 升到 68.29，且只增加约 4-5 ms；Efficiency 同时下降，提醒我们安全收益可能伴随更保守行为。StableDrive 则处理时间接口：旧计划不是越多越好，一周期选择性记忆在 L2、碰撞和跨周期一致性上都优于二周期和四周期，并在 NAVSIM navhard 上比此前最佳高 5.7 EPDMS。前者显式保留规则对象，后者筛选可能过时的历史。

DA-WAM 与 USR-Drive 分别建模动作后果和共享几何。DA-WAM 为每条候选轨迹预测独立 future latent，再让对应后果参与该候选评分；匹配消融中 shared global future 反而低于 no future，说明未来特征若与动作错配会成为噪声。USR-Drive 让 dense 3D Gaussian 与 sparse box 在共享 metric coordinate 中联合去噪，nuScenes 同时达到 27.55 PSNR 与 0.552 detection mAP，且 box-only 与去掉 UPE 都明显崩溃。前者在规划中对齐动作与后果，后者在场景表示中对齐表面与实例；对应关系的消融比总分更能解释模块作用。

测试方向则把代理证据和推理能力拆开审计。Scape 用少量同场景 target-surrogate pair 校正大量仿真标签，再为每个场景给出 conformal 区间；它在 nuPlan 用少 20%-60% 的配对标签达到强基线全预算表现，但明确不声称城市 OOD 下仍保持覆盖保证。CAViAR 在 2,249 个真实事故/近失视频上发现，六个 VLM 的昼夜识别接近 99%，事故类型 accuracy 却低于 majority baseline，规则违反 judge score 只有 0.42-0.82/5。阅读这两篇时，需要分别检查区间覆盖条件和各类风险的表现。

对雷达中心时空占据与场景表征，本周没有一篇真正完成 radar occupancy 的新稿达到录用线，Multi-Observer 的负结果提供了后续对照的依据。它提示后续工作应区分“精确位置证据”和“存在性延续证据”，把 observer、刷新率、遮挡和 covariance 保留到 occupied/free/unknown 更新中；USR-Drive 又明确把缺少 global state、长期身份和 4D tracking 列为限制。后续可检验用校准后的雷达证据维护长期对象或占据身份，同时记录量测可靠性。

- 优先保留能推翻朴素假设的论文：雷达融合不一定提高误差、共享未来可能低于无未来、更多历史可能更差、微调大 VLM 不一定改善因果映射、廉价仿真标签可能污染预测器。只展示正向 headline、没有匹配对照的工作降权。
- `GaussianDWM++` 规模和任务覆盖很大，但训练使用 16 张 A100，所谓 planning-oriented reasoning 主要是 benchmark QA/forecasting，不是规划闭环，资产也处于待发布状态；在本期已有更直接统一表示证据时不再占用名额。综述、纯检测和与道路驾驶仅标题相关的候选均未录用。
- 出版状态逐篇核验：Traffic Element Awareness 同时保留 ECCV 2026 官方页与 arXiv；G-MARK 和 CAViAR 的作者分别在 arXiv comments 声明 ICMLA 2026 oral 与 ECCV 2026 DriveX Workshop 录用，但正式论文页尚未发布，因此明确标为 accepted 并保留 arXiv 主入口；其余只确认预印本。每份详细报告还复核作者单位、数字、图片和资产可用性，Multi-Observer 与 DA-WAM 的占位仓库不再写成可用代码。

## 可靠性评估

- **9.3 | Traffic Element Awareness**：四 benchmark、六 planner、CARLA 闭环、噪声与结构消融齐全；主要风险是深度/拓扑组合失效和效率下降的行为含义。
- **9.1 | Multi-Observer Localization**：真实路口、独立参考车、单传感器与刷新率/遮挡分层完整，负结果透明；只有 19 段单点位数据且传感器能力失衡。
- **8.9 | Scape**：数据分离、paired-label 曲线、OOD 与 conformal width 证据完整，还有实体 Go2；自动驾驶仍是 sim-to-sim，真实场景覆盖有限。
- **8.8 | StableDrive**：完整集、专门转换子集、NAVSIM navhard、历史长度与成本对照充分；缺真实闭环、多 seed 和代码资产。
- **8.8 | DA-WAM**：action-specific future、hard negative 和候选数消融直接支撑接口主张；leaderboard 领先仅 0.2 分，反事实 latent 无非 expert 真值。
- **8.8 | CAViAR**：真实数据、跨域与同域对照、balanced metric 和歧义处理扎实；标注及 LLM judge 仍受单视角与主观性约束。
- **8.7 | G-MARK**：来源/partner removal 消融和带宽数字清楚，代码已开放；上游感知被视作已完成，缺网络扰动和闭环规划。
- **8.6 | USR-Drive**：重建、检测、跨域和联合去噪消融形成闭环；1.418B 模型、50 步离线推理，缺长期身份、规划终点和公开代码。

## 应用场景与讨论线索

- 协同感知：把 G-MARK 的 provenance/visibility/conflict 与 Multi-Observer 的 covariance、refresh rate、match availability 合并为协同 evidence layer；先决定远端证据是收紧位置、延长存在性还是应拒绝，再更新融合状态。
- 端到端规划：把 Traffic Element 的稀疏规则条件和 StableDrive 的 selective temporal memory 放入同一 planner，重点测试红绿灯切换、起步、临时标志和错误 topology 下是否会错误继承上一周期动作。
- 世界模型：在 DA-WAM 的 candidate-specific latent 上加入可解码 occupancy/agent state，并借 USR-Drive 的 metric anchor 约束对象与表面；用 paired simulator 检查每条候选未来是否真对应其动作，而不只看最终 PDMS。
- 测试闭环：用 CAViAR 的事件、角色、规则 ontology 定义场景条件，让 Scape 估计各类场景下的真实表现和区间；区间过宽或责任证据不足时触发人工/高保真复测，而不是强制输出单一判断。
- 雷达 Occupancy：优先探索“存在性与几何精度分离的长期占据记忆”。雷达可在遮挡时延长 object/occupancy hypothesis，但只有通过创新一致性和可观测性校准后才缩小空间 covariance；用真实路侧多观察者数据评价 calibration、identity continuity 和下游规划风险。
- 组会讨论：统一场景状态中，哪些证据应该被融合成一个值，哪些必须永远保留来源、时间、反事实动作和不确定性，直到具体任务来决定？
