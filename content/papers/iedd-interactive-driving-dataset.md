## 一句话定位

IEDD 是一套从 Lyft Level 5、Waymo Open Motion Dataset、nuPlan、INTERACTION 和 SIND 五个既有自然驾驶轨迹库中挖掘交互事件的派生数据集：它把 7,313,985 个自车中心交互片段、物理强度与效率指标、轨迹重建 BEV 视频以及分层问答对齐到同一条 provenance 链。本期收录它，不是因为数据量数字本身，而是因为它提供了从真实轨迹检索、可解释量化到 VLM/VLA 离线诊断的完整生产流水线，同时公开了一个重要反例：专门微调可以把物理量估计误差大幅压低，却可能破坏未参与训练的反事实推理能力。

## 论文要解决的问题

面向驾驶交互的训练数据存在两个断层。第一，常规自然驾驶日志以直行和稳定跟车为主，汇入、交叉、对向会车等需要协商的长尾片段不易被直接检索；第二，轨迹、视觉表示与语言监督往往来自不同流程，缺少可追溯的时间对齐和物理依据。重新采集一套多城市、多传感器数据成本很高，而且不能自动解决交互片段稀疏的问题。

IEDD 选择复用五个公开轨迹库。它只使用轨迹、场景标识、时间戳、目标类别等运动层记录，不把源数据的相机图像、LiDAR 点云或原始视频重新包装成新数据。论文的核心问题因此不是“如何采到更多传感器数据”，而是“如何从已有轨迹中系统找出交互、给交互赋予可解释的物理量，并生成与轨迹严格对齐的视觉和语言任务”。

## 方法和系统设计

- **统一轨迹与事件切片**：五类源数据先被重采样到 0.1 秒时间分辨率，清除无效点，并通过有限差分、角度展开和对称滑窗平滑航向。算法随后以空间距离和时间差搜索轨迹交点，用双指针限制局部时间窗口，再依据轨迹重合与相对航向把双主体事件分为跟车、汇入、交叉和对向四类，最后围绕自车聚合存在时空重叠的多主体交互组。
- **交互强度与通行效率量化**：每个片段记录随时间变化的交互强度 Q_i，并组合时空接近、相对运动和方向相关的人工势场描述风险压力。另一个效率分数 E_Veh 是路径一致性、时间效率和加速度平顺性的乘积。论文明确说明人工势场只是可扩展的事后描述量，不是闭环规划器，也不足以完整表达让行权、强制汇入等策略博弈。
- **可解释语义链**：连续运动被离散为加速、转向、让行等行为原子，相邻同类原子被压缩为带起止时间的行为链；系统以强度峰值为锚点，把交互拆为接近、交互和结果三个阶段，并保留主体角色、方位、路权和强度等级。语言不是自由生成，而是由结构化槽位和规则模板约束，以减少与轨迹不一致的描述。
- **轨迹驱动的多模态合成**：以交互峰值时刻的自车位姿建立统一坐标系，将真实轨迹渲染为带历史轨迹的 BEV 视频，并把行为区间与帧索引对齐。这里的“视觉”是轨迹重建的无遮挡俯视图，不是原始道路图像；它提高了五种数据源之间的兼容性，但也移除了外观、遮挡与传感器退化。
- **IEDD-VQA 四级任务**：L1 测交互主体与类型的感知识别，L2 测行为描述，L3 测交互强度和效率等物理量，L4 测改变自车动作后可能后果的反事实推理。训练集只提供具有确定轨迹标签的 L1-L3，测试集为 100 个典型场景提供完整 L1-L4 链；L4 被刻意保留为未见任务，以检验分布外推理，而不是把开放式答案当作唯一物理真值。
- **数据与代码组织**：IEDD 按五个来源分别发布 CSV，IEDD-VQA 以 JSON 发布训练、测试和 CoT 测试记录，BEV 视频以 MP4 关联到问答样本。官方代码依次提供轨迹到视觉与动作语义、问答构造、L4 反事实追加和 benchmark 评测四个工具。

## 实验结论与证据

### 数据规模与构成

论文报告 IEDD 共包含 **7,313,985 个交互片段**，其中 **6,655,349 个为多主体案例**，另有 658,636 个双主体案例；按类型分为 619,488 个对向、1,624,143 个跟车、1,389,849 个汇入和 3,680,505 个交叉片段。多主体占比约 91.0%。这些数字计数的是算法从轨迹中切出的交互样本，不是 7,313,985 次独立采集、独立道路场景或人工确认的危险事件。

五个底层来源的角色不同：Lyft Level 5、Waymo 和 nuPlan 提供大规模运动预测或规划日志中的轨迹与场景记录，INTERACTION 提供多国复杂交互轨迹，SIND 提供中国信号交叉口的无人机轨迹。IEDD 不重新分发它们的原始传感器记录；复现者仍需分别取得合法访问权。

### 零样本、CoT 与评测器

论文从 100 个测试场景的每段视频均匀采样 6 帧、统一为 512 x 512，并只在第一轮多轮对话中提供视觉上下文。十个主流 VLM 的零样本结果中，Llama-4-Maverick 的 WIS 为 0.342，Qwen2.5-VL-7B 为 0.275，Gemini-2.5-Flash 为 0.209，GPT-4o 为 0.200，Claude-3-Haiku 为 0.093。这说明模型排名与是否闭源或参数更大并不单调，但测试集只有 100 个典型交互场景，不能外推为一般驾驶能力排名。

L3 是最明显的共同瓶颈：零样本 Qwen2.5-VL-7B 的物理量 MAE 为 1855.5，GPT-4o 为 1358.1。加入 CoT 后，Qwen2.5-VL-7B 的 MAE 降到 9.73，WIS 从 0.275 升到 0.289；与此同时，多种模型在目标定位、行为描述或其他分项上出现负增益。因此，实验更稳妥的结论是结构化推理提示有时能帮助模型读出模板化物理关系，而不是模型已经从 BEV 图像学会精确的真实世界动力学。

开放式 L4 由 GLM-4.7 评分。论文用三名自动驾驶背景的博士级标注者检查其一致性，报告 Pearson 相关系数 0.81 +/- 0.03、Spearman 相关系数 0.78 +/- 0.04、MAE 1.22 +/- 0.12。相关性支持它作为大规模近似评测器，但没有消除 judge 的模型偏好，也没有给反事实答案建立可执行轨迹层的物理验证。

### LoRA 微调与负面结果

论文以 Qwen2.5-VL-7B-Instruct 为底座，用两张 Xiyun C500、总 batch size 128、学习率 5e-5 和两轮 LoRA 训练，最终验证损失为 0.0993。由于训练只含 L1-L3，作者使用不含 L4 的 WIS' 比较域内能力：微调将 WIS' 从 0.1475 提高到 0.2636，将 L3 MAE 从 1855.55 降到 0.3036，并把 L3 逻辑准确率从 0.15 提高到 0.53。

但收益伴随两个关键反例。第一，在微调模型上继续加入 CoT，WIS' 反而从 0.2636 降到 0.2336。第二，未参与训练的 L4 反事实推理分从基线 4.66 降到 0.19。前者表明显式推理可能干扰已经适配的回答格式，后者表明模型可能记住数据集的域内模板和数值映射，同时遗忘开放式推理能力。因而这组实验支持“IEDD 适合做任务适配与遗忘诊断”，并不支持“微调后模型成为更全面的驾驶决策专家”。

## 应用场景与启发

- **交互场景检索与长尾采样**：可按来源、场景 ID、主体、时间窗、交互类型和强度筛选训练或测试子集，用于预测、风险估计和规划器的离线回放。更可靠的做法是先按原始 scene 或 scenario 分组，再切分训练与测试，避免同一源场景的相邻片段跨集合。
- **VLM/VLA 分层诊断**：L1-L4 把“看见主体、描述行为、估计物理量、推演反事实”拆开，适合定位模型究竟卡在感知、语言映射还是因果外推。但它更接近离线理解 benchmark，不应直接替代闭环驾驶测试。
- **可追溯的数据增强**：论文保留源数据名、原始场景或 scenario ID、主体 ID、帧或时间区间、数据划分等 provenance 字段，为把派生样本追溯到授权源记录提供基础。后续可以进一步发布按 provenance 分组的去重清单、近邻片段簇和跨数据集冲突报告。
- **方法启发**：最值得继续做的是在域内适配时加入通用任务 replay、反事实一致性正则或保留模型约束，明确优化 L3 数值能力是否必然牺牲 L4；另一个方向是把 L4 答案落成候选轨迹，再用可交互仿真验证因果和安全，而不是只由语言 judge 评分。
- **讨论问题**：当 BEV 由已知完整轨迹重建且无遮挡时，模型是在学习驾驶交互，还是在读取一种高度规整的数据可视化？加入有限视野、定位噪声和感知漏检后，当前 L1-L4 排名会怎样变化？

## 局限与阅读风险

- **不是新采集传感器数据**：IEDD 的 7.31M 规模来自五个公开轨迹库的再切片与聚合；原始相机、LiDAR 和视频未被使用或重新发布。BEV 是轨迹渲染结果，缺少行人目光、手势、刹车灯、转向灯、遮挡和天气退化等外观微语义。
- **片段数不等于独立证据数**：同一原始场景、主体轨迹或时间邻域可能产生多个交互片段，多主体聚合也会放大样本数。把 IEDD 与五个源库或其他派生数据混用时，必须按 provenance 做 scene 级去重与分组切分，否则可能出现训练测试泄漏或重复加权。
- **异构来源仍有域偏差**：五个底层库在城市、交通规则、采样频率、地图质量、传感配置和标注格式上不同。统一坐标与 0.1 秒重采样只能统一接口，不能消除地域和采集协议偏差。
- **标签含有规则假设**：事件阈值、类别自适应权重、人工势场、行为原子和语言模板都由设计者预先定义。它们提高了规模与一致性，却可能漏掉模糊意图、礼让协商、路权冲突和非典型人类解释；物理指标是事后描述，不是策略最优性真值。
- **viewer 与归档可用性需要分开判断**：本轮候选核验在 Hugging Face 数据查看器中观察到异常，且尚未逐个压缩包进行 schema smoke test。在线 viewer 失败不等于 Zenodo 或原始归档损坏，但也意味着不能只凭数据页存在就宣称所有样本可直接加载；复现应下载固定版本并校验文件、字段与样本数。
- **反事实没有唯一物理真值**：L4 仅出现在测试集，答案由模板和语言评测器判断，没有在可交互交通环境中执行。GLM-4.7 与专家评分相关，仍不等价于碰撞、舒适性、通行效率或策略可行性的闭环指标。
- **不存在闭环驾驶验证**：论文没有训练并执行完整的感知-规划-控制系统，也没有车辆动力学、反应式交通参与者或实车道路实验。数据集能支持闭环研究，不代表论文已经证明它能改善闭环规划。

## 后续跟进

- 从正式 Scientific Data DOI 固定论文版本，同时记录 GitHub commit、Hugging Face revision 和 Zenodo DOI；不要只依赖会变化的在线 viewer。
- 最小数据复现先选一个底层来源，按官方脚本依次运行轨迹预处理、交互挖掘、`IEDD-traj2VisAct.py`、`IEDD-2vqa.py`、`IEDD-traj2Q6.py` 和 `IEDD-benchmark.py`，核对来源 ID、时间窗、行为标签与视频帧是否可反向定位。
- 对五个压缩包逐一做 schema、缺失值、唯一键和样本数检查；以原始 scene 或 scenario 为单位统计片段重叠，建立 train/test provenance 交集为零的验证项。
- 复现 Qwen2.5-VL-7B 的四个关键设置：零样本、零样本加 CoT、LoRA 微调、LoRA 微调加 CoT，同时报告 L1-L4 全部分项，重点确认 MAE 巨幅变化是否受输出解析或数值尺度影响。
- 在一个小型反应式仿真子集里，把 L4 回答转换为明确候选动作或轨迹，并用碰撞、TTC、进度和舒适性复核；只有这一层成立后，才能讨论 IEDD-VQA 分数对闭环驾驶的预测力。
